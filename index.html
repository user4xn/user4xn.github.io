Agent engineering

I run my own AI agent team.

Not one chatbot with a long prompt — a small office of specialised agents, each with its own profile, tools and permissions, working on real repositories and real servers. It writes code, reviews it, verifies it, and reports back over Telegram while I am away from the keyboard.

  • Roles, not a monolith. A chief of staff routes work; a PM scopes it; an engineer builds it; a QA agent verifies it in a separate context so nothing self-approves.
  • Policy-level permissions. Sub-agents get read-only Git access, a build guard blocks memory-killing commands on a 2 GB host, and releases stay a human decision.
  • Observability, because agents lie. Live activity wall, cron digests, memory watchdog and log tails — the work is only "done" when the evidence is on screen.

About

I started as a web developer in 2019 and have spent most of my time since on the part of the product nobody sees: pricing rules, ledgers, queues, integrations, migrations. At Komerce I work on the logistics platform — the algorithms that price a shipment, move balance, and settle a transaction — and on the integrations with JNE, SICEPAT, Ninja, SAP, SPX and LION.

I like Clean Architecture not as ceremony but because it makes change cheap: when a carrier changes its API, or a payment provider changes its callback, the blast radius should be one package. I also lean on AI-assisted workflows (MCP tooling, agentic review) to keep the boring parts fast — while keeping ownership of the code I ship.
